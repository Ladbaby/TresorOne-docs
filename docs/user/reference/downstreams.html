🔌 Downstreams

A downstream is an LLM provider endpoint TresorOne calls on your behalf — OpenAI, Anthropic, Google Gemini, a self-hosted OpenAI-compatible gateway, etc. The Downstreams page is where you create, edit, and delete them.

📐 Responsive List Layout​

The Downstreams screen uses a LayoutBuilder to choose between two layouts at 720 logical pixels:

🖥️ Wide (≥ 720 px) — Master / Detail​

PaneWidthContents
Left (master)280 pxSearch field, scrollable ListView of _ProviderRow items, sticky "Add Provider" button at the bottom
Right (detail)ExpandedSelected provider's DownstreamDetail (inline-editable)

When nothing is selected the right pane shows an empty-state card prompting you to select a provider.

📱 Phone (< 720 px) — List-Only​

The master pane takes the full width; tapping a row pushes _DetailOnlyRoute onto the Navigator stack. The visual contract is identical to the wide layout — same widgets, same actions — just on a separate route.

Tip: The split point is tuned for tablets held in portrait mode. Resize the window in development to see both layouts live.

🔘 Provider Row​

Each row in the master list shows:

  • 🟢 ModelIcon — the vendor's logo, resolved through the daemon's /api/icons/{modelID} endpoint with a bundled-asset fallback
  • 🏷️ Provider name (with overflow ellipsis on long names)
  • ✅ _OnChip — green ON / grey OFF pill indicating whether the provider is enabled

A search TextField at the top filters by name as you type; the empty state appears when no providers match.

✏️ Inline-Editable Detail Pane​

DownstreamDetail is fully inline-editable — every field commits to the server on onEditingComplete / onFieldSubmitted rather than going through a form-then-save flow. From top to bottom the detail pane shows:

Header​

  • 📷 ModelIcon for the provider
  • ✏️ Inline TextFormField for the name — commits when you press Enter or move focus away
  • 🗑️ Delete button — opens a confirmation dialog and cascade-removes references in rules and aliases

🔌 API FORMATS​

Wrap of FilterChips for the four supported formats:

  • openai — Chat Completions (/v1/chat/completions)
  • openai_responses — OpenAI Responses API (/v1/responses)
  • anthropic — Anthropic Messages (/v1/messages)
  • gemini — Google Gemini (/v1beta/models/{model}:generateContent)

Each chip has a vendor-logo avatar. Toggling sends a patch(api_formats: [...]) with the sorted payload so reloads don't get reordered "noisy diffs".

Tip: Multi-format downstreams let Tresor's auto-translation route requests across protocols without any explicit rule. See the Tresor user guide for the full reference.

🔑 API KEY​

A Container with an eye icon. Tapping the eye calls revealApiKey() to fetch the unmasked value from the server and show it inline; tapping again hides it. Typing in the field commits the new value on onEditingComplete. There's a guard against echoing the revealed value back to the field while you're looking at it.

A Fetch Models button is also hosted here — see the Fetch Models dialog below.

🌐 API HOST​

A Container with a link icon + inline TextFormField, plus a copy-URL button next to it. The editor validates the URL scheme before saving; the invalid state stays in the form until you fix it.

🤖 MODELS​

A SectionHeader with the model count and a help icon, plus two action buttons:

  • 🔎 Fetch Models — spinner while fetchModels() runs, then opens the Fetch Models dialog
  • ➕ Add Model — reveals an inline input row with Add button

Beneath the actions, a responsive _ModelGrid renders 1–4 columns depending on available width. Each model is a _ModelChip (icon + ID + remove IconButton) and is swipe-to-deletable via flutter_slidable — swipe from right to left to expose the delete action.

📋 Downstream Form (3 Tabs)​

The form screen (/downstreams/new and /downstreams/:id) is a SegmentedButton-driven tabbed interface with three sections mirroring the Cherry Studio downstream editor. The save/cancel action row lives outside the scrollable so it's always reachable.

Tab: General​

FieldRequiredNotes
🏷️ Name✅ YesMin 2 characters. Used as the display name.
🌐 Base URL✅ YesMust be a valid URL. Help tooltip explains what goes here (e.g. https://api.openai.com).
🔑 API Key◯ OptionalObscured with visibility toggle. Helper text notes the existing key is hidden by the server.

Tab: Models​

ElementDescription
SectionHeaderTitle + optional subtitle
🏷️ Model Chip WrapEach chip shows ModelIcon + model ID + × remove button
➕ Add Model buttonReveals an inline TextFormField + Add button
🔎 Fetch Models buttonCalls fetchModelsForNew() for an unsaved downstream or fetchModels() for a saved one and merges results into the grid

Tab: API​

SectionHeader + the same Wrap of FilterChips for the four API formats, with vendor logos. Toggling chips commits immediately when the downstream is saved, or updates the in-memory form when creating new.

Action Row​

  • ↩️ Cancel — OutlinedButton, pops the route
  • ✅ Create / Save — FilledButton, triggers _save() which calls create() or update() on the provider

Tip: The form keeps _save() consistent across new and existing — the screen constructor takes an optional Downstream and the same code path handles both.

🔎 Fetch Models Dialog​

FetchModelsDialog is opened from both the detail pane and the form's Models tab.

ElementDescription
🏷️ Title"Fetch Models from Provider"
🟢 Status badge"N added" with an animated counter
❌ Close× button (top-right)
📜 ListScrollable ListView of _ModelRow items (icon + model ID + state button)
⏳ State machine_AddButton → _AddedPill (spinner when busy) → error icon on failure
✅ Done buttonCloses the dialog and returns to whatever pane opened it

Each + Add button fires a separate POST /api/downstreams/{id}/models call so you can pick exactly what to import. Models already on the downstream appear as Added (non-tappable) so you don't accidentally add them twice.

After every CRUD operation that introduces new model IDs (alias create/update, downstream create/update), the providers kick off an icon index refresh so newly-referenced models get their icons on the next render.

🌐 Icon Resolution​

Model icons are resolved through three layers, in order:

  1. Daemon SVG — fetched from /api/icons/{modelID} via the daemon's icon cache, with token-bucket rate limiting and in-flight coalescing so duplicate model IDs only hit the network once
  2. Bundled asset — IconRegistry.resolveLocal looks the model ID up in a pattern table that mirrors Tresor's icons.Resolve and returns one of assets/icons/*.svg (anthropic.svg, openai-completions.svg, openai-responses.svg, gemini.svg)
  3. auto_awesome_outlined — Material icon used when neither source is available

A new provider row gets auto_awesome_outlined until you fetch models, at which point the icons refresh and the row switches to a vendor logo if one is recognized.

🗑️ Deleting a Downstream​

The delete button (top-right of the detail pane header) opens a confirmation dialog. On confirm, TresorOne sends the DELETE call and the daemon performs the cascade:

  • 💥 Removes the downstream from rule match_downstreams arrays
  • 💥 Deletes any aliases that pointed at it

A snackbar confirms the deletion and the row disappears from the master list.
