# 📦 Installation

TresorOne is distributed as a single Flutter app. Each [GitHub Release](https://github.com/ladbaby/TresorOne/releases) attaches one installer per supported platform plus a `Source code` archive.

## 📥 Download a Release

Pick the row that matches your platform from the table below and click the asset name to start the download:

| Platform | Asset | Type | Notes |
|---|---|---|---|
| 🪟 **Windows** | [Setup (x64)](https://github.com/ladbaby/TresorOne/releases/latest) | `TresorOne-windows-x64-setup.exe` | Standard installer; places the app under `%LOCALAPPDATA%\Programs\TresorOne\` and adds a Start Menu + desktop shortcut |
| 🪟 **Windows (portable)** | [Portable (x64)](https://github.com/ladbaby/TresorOne/releases/latest) | `TresorOne-windows-x64-portable.zip` | No installer — unzip and run `tresor_one.exe` from anywhere; useful on machines where you can't install |
| 🍎 **macOS** | [Universal](https://github.com/ladbaby/TresorOne/releases/latest) | `TresorOne-macos-universal.tar.gz` | Single universal binary (Intel + Apple Silicon); extract and drag `TresorOne.app` into **Applications** |
| 🐧 **Linux** | [tar.gz (x64)](https://github.com/ladbaby/TresorOne/releases/latest) | `TresorOne-linux-x64.tar.gz` | x86_64 tarball; extract and run the bundled `tresor_one` binary |
| 🤖 **Android** | [arm64](https://github.com/ladbaby/TresorOne/releases/latest) | `TresorOne-android-arm64-release.apk` | arm64-only sideload APK. Install via `adb install` or by opening the file on the device |
| 🍎 **iOS** | TestFlight (separate program) | — | iOS builds are not published as release assets — request TestFlight access through a [GitHub issue](https://github.com/ladbaby/TresorOne/issues) |

:::info
Click **"… download all" → "Download as zip"** in the GitHub UI to grab the `Source code (zip)` archive along with the platform-specific binaries, or use the [`checksums.txt`](https://github.com/ladbaby/TresorOne/releases/latest) file to verify any single asset before running it.
:::

### Picking the right download

- **Windows users** — start with the **Setup** installer unless you need to keep the app on a USB stick or run from a folder you fully control (corporate machines, restricted accounts); in that case use the **Portable** zip.
- **macOS users on Apple Silicon** — the **Universal** tarball is the right pick regardless of architecture. Do **not** look for an `aarch64`-specific artifact; there isn't one.
- **Linux users** — there is no `.deb`, `.rpm`, or `.AppImage` in the release. Extract the tarball anywhere on your `$PATH` (e.g. `~/.local/bin/`) and run `tresor_one`.

## 🚀 Install Steps per Platform

<Tabs>
  <TabItem value="windows-setup" label="Windows (Setup)">
    1. Run `TresorOne-windows-x64-setup.exe`
    2. If Windows SmartScreen blocks the first launch, click **More info → Run anyway**
    3. The installer places the app under `%LOCALAPPDATA%\Programs\TresorOne\` and creates a Start Menu shortcut. Updates install over the same directory.
  </TabItem>
  <TabItem value="windows-portable" label="Windows (Portable)">
    1. Extract `TresorOne-windows-x64-portable.zip` to a folder of your choice (e.g. `C:\Apps\TresorOne\`)
    2. Double-click `tresor_one.exe` to launch
    3. (Optional) Pin the executable to the Start Menu or taskbar for future use
  </TabItem>
  <TabItem value="macos" label="macOS">
    1. Extract `TresorOne-macos-universal.tar.gz` — it produces a `TresorOne.app` bundle
    2. Drag `TresorOne.app` into your **Applications** folder
    3. The first launch may require **right-click → Open** to bypass the unidentified developer prompt. Subsequent launches work normally.
  </TabItem>
  <TabItem value="linux" label="Linux">
    1. Extract the archive:

       ```bash
       tar -xzf TresorOne-linux-x64.tar.gz
       ```

    2. Make the binary executable and add it to your `$PATH`:

       ```bash
       chmod +x tresor_one
       mv tresor_one ~/.local/bin/
       ```

    3. Launch from a terminal with `tresor_one`, or create a `.desktop` file under `~/.local/share/applications/` if you want a launcher icon.

    :::tip
    On Wayland, you may need to install `libgtk-3-0` and `libnotify-bin` if your distribution doesn't bundle them by default. Most modern distros ship both out of the box.
    :::
  </TabItem>
  <TabItem value="android" label="Android">
    1. Download `TresorOne-android-arm64-release.apk` from the release page
    2. Sideload via ADB:

       ```bash
       adb install -r TresorOne-android-arm64-release.apk
       ```

       Or copy the APK onto the device and tap to install.

    :::tip
    Enable **Install unknown apps** for the file manager or browser you sideload from. Most launchers will guide you there automatically when you open the APK.
    :::

    :::caution
    The release APK is **arm64-only**. x86_64 Android emulators (e.g. the default Android Studio AVD on some hosts) will refuse to install it. Use an arm64 AVD image, or build from source for x86_64.
    :::
  </TabItem>
  <TabItem value="ios" label="iOS">
    iOS builds are **not attached to GitHub releases**. To install TresorOne on iOS:

    1. Open a [GitHub issue](https://github.com/ladbaby/TresorOne/issues) requesting TestFlight access — provide your Apple ID email so we can add you to the beta group
    2. Once accepted, install **TestFlight** from the App Store
    3. Accept the invitation email, then install TresorOne from inside TestFlight
    4. TestFlight builds expire after 90 days — re-install when prompted

    :::info
    For local development, building iOS still requires Xcode and an Apple Developer account. See [Build from Source](#build-from-source) below.
    :::
  </TabItem>
</Tabs>

## Build from Source

For developers contributing patches, or when you need the latest unreleased changes:

### Prerequisites

- 🦋 **Flutter 3.27+** with Dart 3.12+
- 🛠️ Platform toolchain — Xcode (macOS/iOS), Android Studio + SDK (Android), Visual Studio 2022 with the **Desktop development with C++** workload (Windows), or `clang` and `libgtk-3-dev` (Linux)

### Clone & run

```bash
git clone https://github.com/ladbaby/TresorOne.git
cd TresorOne
flutter pub get
dart run build_runner build
flutter run -d <device-id>      # e.g. -d windows, -d macos, -d linux
```

### Build a release artifact

<Tabs>
  <TabItem value="windows" label="Windows">
    ```bash
    flutter build windows --release
    # Output: build/windows/runner/Release/tresor_one.exe
    ```
  </TabItem>
  <TabItem value="macos" label="macOS">
    ```bash
    flutter build macos --release
    # Output: build/macos/Build/Products/Release/TresorOne.app
    ```
  </TabItem>
  <TabItem value="linux" label="Linux">
    ```bash
    flutter build linux --release
    # Output: build/linux/x64/release/bundle/tresor_one
    ```
  </TabItem>
  <TabItem value="android" label="Android">
    ```bash
    # Default (matches the GitHub Release asset):
    flutter build apk --release --target-platform android-arm64
    # Output: build/app/outputs/flutter-apk/app-release.apk

    # x86_64 AVD build (not shipped to GitHub Releases):
    flutter build apk --release --target-platform android-x64
    ```

## 📂 Where TresorOne Stores Data

TresorOne uses standard Flutter conventions for app data:

| Data | Location |
|---|---|
| Known remotes | Encrypted via `flutter_secure_storage` (Keychain / Keystore / libsecret / DPAPI depending on platform) |
| Theme / palette / text size / default tab | `SharedPreferences` |
| Log buffer (in-memory) | RAM only — lost on app close |
| Local-mode daemon artifacts | `path_provider` `getApplicationSupportDirectory()` |

The Tresor daemon itself stores its config + SQLite DB wherever the original Tresor install put them — TresorOne never writes to those locations directly; it always goes through the daemon's REST API.

## 🚀 First Run

When you launch TresorOne for the first time, the **Connect** screen offers two modes:

- 🚀 **Default (Local Mode)** — one-click: download the Tresor binary from GitHub Releases, auto-generate a YAML config, spawn the daemon as a child process, and auto-connect
- ☁️ **Advanced (Remote Connection)** — enter an endpoint (`http://127.0.0.1:11510`) and an admin password to connect to any running Tresor daemon

See [Connection Modes](connection-modes) for the full walkthrough of both flows.

## 🆘 Troubleshooting

### Windows SmartScreen blocks the installer

> **Tip:** Click **More info → Run anyway**. The installer is unsigned in development builds; release builds are signed before being attached to a GitHub Release.

### macOS says the app is from an unidentified developer

> **Tip:** Right-click the `.app` in Finder, choose **Open**, then confirm in the prompt. After the first open, double-clicking works normally.

### Linux: missing GTK libraries

> **Tip:** Install the runtime dependencies: `sudo apt install libgtk-3-0 libnotify-bin` (Debian/Ubuntu) or your distro's equivalent. The release tarball does not bundle GTK.

### Android emulator fails with "INSTALL_FAILED_NO_MATCHING_ABIS"

> **Tip:** The release APK is **arm64-only**. Switch your AVD to an `arm64-v8a` system image, or build from source with `--target-platform android-x64`.

### App is sluggish on first launch

> **Tip:** TresorOne performs initialization (loading plugin metadata, refreshing the secure-storage cache, etc.) on startup. Subsequent launches reuse cached state and are noticeably faster.
