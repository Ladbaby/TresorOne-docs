# 🔌 Connection Modes

When TresorOne launches and the app is not already connected to a Tresor daemon, the **Connect** screen appears. A `SegmentedButton` at the top lets you pick between two connection modes:

| Mode | Best For | What Happens |
|---|---|---|
| **Default (Local)** | New users, single-machine setups | Downloads the Tresor binary from GitHub Releases, auto-generates a YAML config, spawns the daemon as a child process, and auto-connects |
| **Advanced (Remote)** | Multi-machine setups, pre-existing daemons | Connects to any Tresor daemon reachable by host:port + JWT auth |

You can switch between modes after the first connect using the **mode toggle** in the dashboard sidebar footer.

---

## 🚀 Local Mode (Default)

Local Mode is the **one-click setup**. No manual config, no terminal commands — TresorOne handles everything end-to-end.

### How It Works

```
┌────────────────────┐     ┌────────────────────┐     ┌────────────────────┐
│  Click "Start      │ ──▶ │  Download Tresor   │ ──▶ │  Generate config   │
│  Local Mode"       │     │  binary from       │     │  (~/.tresor.yaml   │
│                    │     │  GitHub Releases   │     │  on disk)          │
└────────────────────┘     └────────────────────┘     └─────────┬──────────┘
                                                                │
                                                                ▼
┌────────────────────┐     ┌────────────────────┐     ┌────────────────────┐
│  Auto-connect +    │ ◀── │  Health check      │ ◀── │  Spawn daemon as   │
│  navigate to       │     │  polls /health     │     │  child process     │
│  /downstreams      │     │  every 250 ms      │     │  (SIGTERM on exit) │
└────────────────────┘     └────────────────────┘     └────────────────────┘
```

### Progress Dialog

While the setup is in flight, a non-dismissible **Local Mode Progress Dialog** shows the current state:

| State | Visual | Description |
|---|---|---|
| **Downloading** | 📥 Linear progress bar + percentage | Binary is being streamed from GitHub Releases. Shows speed and ETA. |
| **Starting** | ⏳ Spinner + "Waiting for daemon to become ready" | Daemon was spawned; health endpoint is being polled every 250 ms. |
| **Running** | ✅ Green checkmark + "Continue" button | Daemon is up. Tap Continue to land on the Downstreams page. |
| **Error** | ❌ Red icon + error title + process output + Retry/Cancel | Anything went wrong. The dialog shows the failure category (download failed, daemon failed to start, health check timed out) plus any captured stdout/stderr. |

> **Tip:** If the health check times out, check that no firewall is blocking outbound HTTPS to `github.com` or that your daemon's `bind_addr` is reachable. The dialog preserves the most recent daemon output so you can copy it into a bug report.

### What gets generated

The auto-generated config covers the defaults — no downstreams, no aliases, no rules. You then populate it from the dashboard. To pre-seed downstreams you can edit the file before launching:

```yaml
# Auto-generated by TresorOne — feel free to edit.
# Changes via the admin UI write back here atomically.
bind_addr: "127.0.0.1:11510"
db_path: "~/.tresor/tresor.db"
```

:::info
Settings you change from the dashboard after the daemon is up — admin password, proxy mode, log level, etc. — are persisted into the same YAML file automatically. You don't need to keep editing the file manually.
:::

## ☁️ Remote Mode (Advanced)

Remote Mode connects to **any** Tresor daemon reachable over HTTP — on the same machine, on your LAN, or somewhere on the internet.

### Connect screen

The Advanced card on the Connect screen contains:

- 🏷️ **Endpoint** — defaults to `http://127.0.0.1:11510`. Must start with `http://` or `https://`, and must include a host. The validation runs on submit, so partial URLs don't block typing.
- 🔑 **Password** — optional unless the daemon requires it. The password field has a visibility toggle.
- 📜 **Known remotes** — if you have saved remotes from previous sessions, they appear as a scrollable list above the form. Tapping a row prefills the endpoint + password (if it was saved) and starts the connection; a trash-can icon on each row lets you remove it.
- 🔵 **Connect** — submits the form, calls `/api/auth/login`, and navigates to the dashboard on success

### Save & resume

If you successfully connect, the endpoint + admin password are **saved to `flutter_secure_storage`** so the next launch can auto-resume the connection. A "Resuming last connection…" banner appears during this verification.

> **Tip:** Known remotes persist across app updates and reboots. The list lives in secure storage on each platform's keychain / keystore / libsecret / DPAPI.

### Sidebar mode toggle

After you're connected, the **sidebar footer** shows two buttons — **Local** and **Remote** — with the current mode highlighted. Tapping the alternate mode shows a confirmation dialog (since switching ends the active connection) and then either:

- Opens the **Local Mode Progress Dialog** (if switching to Local)
- Opens the **Remote Connect Dialog** with the known-remotes list (if switching to Remote)

You can also tap the **sidebar header** (TresorOne logo + connection indicator) at any time to open the Remote Connect Dialog.

## 🔐 Authentication

Tresor's admin API supports JWT-based session auth. TresorOne uses it transparently:

1. 🔑 On connect, TresorOne POSTs the endpoint + password to `/api/auth/login`
2. 🎫 The daemon returns a JWT, which TresorOne stores in memory and reuses for every subsequent admin call
3. ⏱️ TresorOne auto-refreshes the JWT before it expires (and on any 401 retry) so you never see an unexpected logout
4. 🔄 On login, the JWT is also written to a secure-storage-backed session store so a relaunch resumes without prompting again

### Admin Password

The daemon's `admin_password` is configured in the Tresor YAML config. To change it after launch:

1. ⚙️ Open **Settings → Authentication → Admin Password**
2. 🆕 Enter a new password (and confirm)
3. ✅ Tap **Change** — the daemon immediately logs out the current session and starts using the new credential

To disable password auth entirely (e.g. on a trusted LAN machine), uncheck the **Require password** checkbox before saving.

> **Warning:** Disabling admin password means anyone on the same network can manage your daemons. Enable it for any deployment that isn't on a private LAN.

## 🪪 Multiple Saved Remotes

Multiple remotes can be saved simultaneously — useful for managing **a laptop and a home server**, or **a dev and a prod daemon**. The Connect screen's known-remotes list scrolls vertically, and the **Remote Connect Dialog** from the sidebar footer surfaces the same list at any time.

Each known remote stores:

| Field | Description |
|---|---|
| `displayName` | Human-readable label you set (auto-populated from the endpoint if you didn't customize it) |
| `endpoint` | The URL (e.g. `http://192.168.1.50:11510`) |
| `adminPassword` | Encrypted via secure storage; `null` if the daemon has no password |
| `lastConnectedAt` | Timestamp of the last successful connect |

:::tip
On Android, secure-storage reads can transiently fail right after a cold start if the device hasn't been unlocked yet. TresorOne retries a few times before falling back to prompting for the password.
:::

## 🩺 Health Checks & Reconnect

While you're connected, TresorOne periodically polls the daemon's `/health` endpoint. If the connection drops:

- 🔴 The **Connection Indicator** in the sidebar turns red
- 📣 A **Reconnect Banner** appears at the top of the dashboard with **Reconnect** (re-runs `tryReconnect` against the saved endpoint + password) and **Dismiss** actions
- 🔕 Operations that require the connection show a friendly error until reconnection succeeds

The Daemon itself attempts graceful shutdown on SIGTERM (or window close on Windows/macOS/Linux), so local-mode teardown is clean — TresorOne sends the signal and waits for the process to exit before unmounting.

## 🪟 System Tray (Desktop Only)

On Windows / macOS / Linux, TresorOne installs a **system tray icon** when you minimize the window or close it to the tray:

- 👆 **Left-click the tray icon** — restores the window
- 📋 **Right-click → Show / Exit** — context menu with **Show** and **Exit** options
- 🔄 **Auto-reconnect** — if you left in Local Mode and re-open from tray, TresorOne respawns the daemon if it died while you were away
- ⏰ **Scheduled launch (Windows)** — combine with **Auto Launch** in Settings to have TresorOne start on login and live in the tray until you need it

Mobile builds (Android / iOS) do **not** have a system tray — the foreground/background app lifecycle takes its place.
