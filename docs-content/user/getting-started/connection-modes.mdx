# 🔌 Connection Modes

When TresorOne launches and the app is not already connected to a Tresor gateway, the **Connect** screen appears. A selector at the top lets you pick between two connection modes:

| Mode | Best For | What Happens |
|---|---|---|
| **Default (Local)** | New users, single-machine setups | Downloads the Tresor binary from GitHub Releases, auto-generates a configuration, starts the gateway as a background process, and connects |
| **Advanced (Remote)** | Multi-machine setups, pre-existing gateways | Connects to any Tresor gateway reachable by host:port + password |

You can switch between modes after the first connect using the **mode toggle** in the dashboard sidebar footer.

---

## 🚀 Local Mode (Default)

Local Mode is the **one-click setup**. No manual config, no terminal commands — TresorOne handles everything end-to-end.

### How It Works

```
┌────────────────────┐     ┌────────────────────┐     ┌────────────────────┐
│  Click "Start      │ ──▶ │  Download Tresor   │ ──▶ │  Generate          │
│  Local Mode"       │     │  binary from       │     │  configuration     │
│                    │     │  GitHub Releases   │     │                    │
└────────────────────┘     └────────────────────┘     └─────────┬──────────┘
                                                                │
                                                                ▼
┌────────────────────┐     ┌────────────────────┐     ┌────────────────────┐
│  Auto-connect +    │ ◀── │  Wait for the      │ ◀── │  Start the         │
│  navigate to       │     │  gateway to        │     │  gateway as a      │
│  provider list     │     │  report ready      │     │  background task   │
└────────────────────┘     └────────────────────┘     └────────────────────┘
```

### Progress Dialog

While the setup is in flight, a non-dismissible **Progress** dialog shows the current state:

| State | Visual | Description |
|---|---|---|
| **Downloading** | 📥 Linear progress bar + percentage | Binary is being streamed from GitHub Releases. Shows speed and ETA. |
| **Starting** | ⏳ Spinner + "Waiting for the gateway to become ready" | The gateway was started; the app is waiting for it to report back. |
| **Running** | ✅ Green checkmark + "Continue" button | The gateway is up. Tap Continue to land on the provider list. |
| **Error** | ❌ Red icon + error title + process output + Retry/Cancel | Anything went wrong. The dialog shows the failure category (download failed, gateway failed to start, health check timed out) plus any captured output. |

> **Tip:** If the startup times out, check that no firewall is blocking outbound HTTPS to `github.com`. The dialog preserves the most recent gateway output so you can copy it into a bug report.

### What gets generated

TresorOne creates a fresh configuration with default settings — you can leave it alone and add providers from the app.

:::info
Settings you change from the dashboard after the gateway is up — admin password, proxy mode, log level, etc. — are saved automatically. You don't need to keep editing the file manually.
:::

## ☁️ Remote Mode (Advanced)

Remote Mode connects to **any** Tresor gateway reachable over the network — on the same machine, on your LAN, or somewhere on the internet.

### Connect screen

The Advanced card on the Connect screen contains:

- 🏷️ **Endpoint** — defaults to `http://127.0.0.1:11510`. Must start with `http://` or `https://`, and must include a host.
- 🔑 **Password** — optional unless the gateway requires it. The password field has a visibility toggle.
- 📜 **Saved connections** — if you have saved remotes from previous sessions, they appear as a scrollable list above the form. Tapping a row connects; a remove button on each row lets you delete it.
- 🔵 **Connect** — submits the form and navigates to the dashboard on success

### Save & resume

If you successfully connect, the endpoint + admin password are **saved securely by your operating system** so the next launch can auto-resume the connection. A "Resuming last connection…" banner appears during this verification.

> **Tip:** Saved connections persist across app updates and reboots. The list is stored using your OS's secure storage (Keychain / Keystore / libsecret / DPAPI).

### Sidebar mode toggle

After you're connected, the **sidebar footer** shows two buttons — **Local** and **Remote** — with the current mode highlighted. Tapping the alternate mode shows a confirmation dialog (since switching ends the active connection) and then either:

- Opens the **Local Mode Progress Dialog** (if switching to Local)
- Opens the **Remote Connect Dialog** with the saved-connections list (if switching to Remote)

You can also tap the **sidebar header** (TresorOne logo + connection indicator) at any time to open the Remote Connect Dialog.

## 🔐 Authentication

The Tresor gateway supports password-based session auth. TresorOne uses it transparently:

- 🔑 When you connect with a password, TresorOne signs in for you and keeps the session alive — no repeated logins until the connection drops
- 🔄 On login, the session is also saved to the OS's secure storage so a relaunch resumes without prompting again
- 🔓 If the gateway has no password set, TresorOne connects immediately

### Admin Password

The gateway's admin password is set in the gateway's own configuration. To change it after launch:

1. ⚙️ Open **Settings → Authentication → Admin Password**
2. 🆕 Enter a new password (and confirm)
3. ✅ Tap **Change** — the gateway starts using the new credential immediately

To disable password auth entirely (e.g. on a trusted LAN machine), uncheck the **Require password** checkbox before saving.

> **Warning:** Disabling admin password means anyone on the same network can manage your gateway. Enable it for any deployment that isn't on a private LAN.

## 🪪 Multiple Saved Connections

Multiple connections can be saved simultaneously — useful for managing **a laptop and a home server**, or **a dev and a prod gateway**. The Connect screen's saved-connections list scrolls vertically, and the **Remote Connect Dialog** from the sidebar footer surfaces the same list at any time.

Each saved connection stores:

| Field | Description |
|---|---|
| Display name | Human-readable label (auto-populated from the endpoint if you didn't customize it) |
| Endpoint | The URL (e.g. `http://192.168.1.50:11510`) |
| Password | Saved to your OS's secure storage; missing if the gateway has no password |
| Last connected | When you last connected successfully |

:::tip
On Android, after a reboot you may need to re-enter the saved password once if the device is still locked.
:::

## 🩺 Health Checks & Reconnect

While you're connected, TresorOne periodically checks the gateway's health. If the connection drops:

- 🔴 The **Connection Indicator** in the sidebar turns red
- 📣 A **Reconnect Banner** appears at the top of the dashboard with **Reconnect** (re-runs the connection against the saved endpoint + password) and **Dismiss** actions
- 🔕 Operations that require the connection show a friendly error until reconnection succeeds

When you close TresorOne in Local Mode, the gateway shuts down cleanly in the background — no orphaned processes.

## 🪟 System Tray (Desktop Only)

On Windows / macOS / Linux, TresorOne installs a **system tray icon** when you minimize the window or close it to the tray:

- 👆 **Left-click the tray icon** — restores the window
- 📋 **Right-click → Show / Exit** — context menu with **Show** and **Exit** options
- 🔄 **Auto-reconnect** — if you left in Local Mode and re-open from tray, TresorOne restarts the gateway if it died while you were away
- ⏰ **Scheduled launch (Windows)** — combine with **Auto Launch** in Settings to have TresorOne start on login and live in the tray until you need it

Mobile builds (Android / iOS) do **not** have a system tray — the foreground/background app lifecycle takes its place.
