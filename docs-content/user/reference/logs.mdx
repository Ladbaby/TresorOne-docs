# 📺 Logs

The **Logs** tab is a real-time view of every request the daemon has processed. It streams via Server-Sent Events (SSE), so new entries appear without polling. Click any row to open the **Inspector** — Parsed and Raw views of the captured request/response.

## 📋 Log List

A `ListView.builder` of `LogEntryCard`s sorted newest-first. Each card is two rows:

### Header row

| Element | Description |
|---|---|
| 🕒 Timestamp | HH:MM:SS.mmm in monospace |
| 🎚️ `LogLevelBadge` | Color-coded pill — debug=grey, info=blue, warn=amber, error=red |
| 📡 `MethodBadge` | GET=green, POST=blue, PUT=orange, DELETE=red (and others) |
| 🛣️ Path | Ellipsized |
| 📶 `HttpStatusBadge` | 2xx=green, 4xx=amber, 5xx=red |
| ⏱️ Duration | Monospace; **orange** if > 1 s |

### Body row

- 🤖 Input model ID → ➡️ resolved output model (green)
- 🔌 Downstream name
- 🟣 Alias group chip (when an alias was used; accent tint)
- ❌ Error text (red, when present)
- 💾 Cache hit rate chip (when payload capture is on and cache info is available)

Card background tints by severity:

- 🔴 Red — for errors
- 🟡 Amber — for 4xx responses
- 🟢 Accent (default) — for normal entries

## 🔎 Controls

### 🟢 `_StreamIndicator`

Animated pulsing dot in the app bar showing the SSE state:

| State | Color | Meaning |
|---|---|---|
| 🟢 **Live** | Green | Streaming |
| 🟡 **Paused** | Grey | Stream paused (you tapped pause) |
| 🔴 **Offline** | Red | Disconnected / retrying |

### ⏬ Auto-Scroll Toggle

The arrow_downward / pause_circle_outline button in the app bar:

- ⏬ **Auto-scroll on** (default) — the list follows the newest entry; tapping enters manual scroll mode
- ⏸ **Auto-scroll off** — list freezes where you are; new entries appear at the top but the viewport doesn't move

A `_NewEntriesBanner` appears at the bottom when auto-scroll is off but new entries have arrived. Tap it to jump to the newest.

### 🧹 Clear Buffer

Trash-can icon. Removes every entry from the in-memory buffer and the visible list.

## 🔍 Filter Bar

A single `TextField` at the top filters entries in real time. The match is **free-text across any of**:

| Field | Matched |
|---|---|
| `model` | ✅ |
| `resolvedModel` | ✅ |
| `path` | ✅ |
| `downstreamName` | ✅ |
| `downstreamId` | ✅ |
| `error` | ✅ |
| `aliasGroup` | ✅ |
| `method` | ✅ |
| `status` | ✅ |
| `message` | ✅ |
| `level` | ✅ |

A **Clear** button appears when the filter has any text. Empty state messages adapt to the situation:

- ⚪ "Logs will appear here when requests are processed" (no entries at all)
- 🔍 "No entries match the current filters"

## 🔬 Inspector

Click any log row to navigate to `/logs/inspect/:id`. The Inspector is a full-screen page with an app bar + two tabs:

### 🪪 Meta panel (both tabs)

`Card` of `SelectableText` rows showing the request metadata:

- 📡 Method, 🛣️ Path, 📶 Status, 🤖 Model, 🎯 Resolved, 🔌 Downstream, 🌐 Client IP, 🕒 Captured at

### Tab: Parsed

A toggle to switch between **Markdown rendering** and pretty-printed JSON, plus two cards:

| Card | Content |
|---|---|
| **Request (parsed)** | Content-type badge + parsed body |
| **Response (parsed)** | Content-type badge + parsed body |

Parsed sections are rendered by `_ParsedViewRenderer`:

- **System** — text blocks (system prompt)
- **Messages** — role-styled message cards (🟣 purple=assistant, 🔵 blue=user, 🟢 teal=system) with content blocks
- **Tools** — expandable cards with name, description, and input schema JSON
- **JSON** — raw JSON rendered in monospace for unrecognized top-level fields

Content block types:

| Block | Visual |
|---|---|
| 🅰️ `TextBlock` | Plain text |
| 🤔 `ThinkingBlock` | Collapsible section |
| 🛠️ `ToolUseBlock` | Amber background |
| 📦 `ToolResultBlock` | Green if success, red if error |
| 🖼️ `ImageBlock` | URL as `SelectableText` |
| 📝 `SystemReminderBlock` | Collapsible, tertiary color |

Below the bodies:

- 📊 **`_UsageFooter`** — "N in · N out · N cached"
- ⚠️ **`_IncompleteNotice`** — warning banner for truncated / incomplete captures

### Tab: Raw

Two raw cards:

| Card | Content |
|---|---|
| **Raw client request** | Content-type badge + truncated badge (amber) + copy button + pretty-printed or monospace body |
| **Raw downstream response** | Same layout |

A **Back to Logs** `FilledButton.tonalIcon` returns to the list. If the entry has aged out of the capture buffer (the daemon keeps only the most recent 100 captures), the Inspector renders a 404 with **No captured payload — capture is disabled or entry aged out of cache** and a **Retry** button.

## 📐 Parsed-View Display Order

For every format TresorOne recognizes, the Parsed view **does not** mirror the raw JSON key order. The canonical sections are emitted in the order the model actually consumes the prompt:

| Format | Parsed Order | Source |
|---|---|---|
| **Anthropic Messages** | `tools → system → messages` | [Anthropic tool-use docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching) |
| **OpenAI Chat Completions** | `tools → system → messages` | Follows the convention used by Llama 3 / Qwen chat templates; OpenAI doesn't publish an explicit ordering |
| **OpenAI Responses** | `tools → instructions → input[]` | [Codex agent loop blog](https://openai.com/index/unrolling-the-codex-agent-loop/) |
| **Gemini** | `systemInstruction → tools → contents` | [Google's generate-content example](https://ai.google.dev/api/generate-content) + [caching guide](https://ai.google.dev/gemini-api/docs/caching) |

A small banner with a `?` tooltip appears at the top of the Parsed view for these formats so the order discrepancy from raw JSON is visible. Unrecognized top-level fields (`generationConfig`, `safetySettings`, `temperature`, etc.) still show up under the canonical sections as pretty-printed JSON.

## 📡 Stream Lifecycle

The SSE connection is only active while the **Logs** route is in focus. Switching to another dashboard tab disconnects the stream to save resources; switching back reconnects automatically with exponential backoff (1 s → 30 s).

> **Warning:** The stream is intentionally **polled** rather than chunked — Flutter's `http` package doesn't natively consume streaming responses, so TresorOne polls with short-lived requests every second. On a quiet network, entries can take up to 1 s to appear; on a busy daemon, multiple entries can arrive in one poll cycle.

## ⚙️ Payload Capture

Payload inspection is **opt-in**. To enable it:

1. ⚙️ Open **Settings → Basic Configuration → Payload Capture**
2. ✅ Toggle on — the daemon restarts capture (max 100 most-recent requests; ~1 MiB per direction)

The setting persists to the daemon's YAML config. With it off, the Inspector shows 404s for every entry; with it on, the most recent 100 entries are inspectable.

:::info
Payload capture adds a small per-request memory cost (capped at ~1 MiB per direction) and only stores the **original** request — before any plugin runs. This is intentional, so the inspector shows what clients actually sent, not the post-pipeline output.
:::
