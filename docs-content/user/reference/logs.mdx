# 📺 Logs

The **Logs** tab is a real-time view of every request the gateway has processed. New entries appear as they happen, and clicking any row opens the **Inspector** — Parsed and Raw views of the captured request/response.

## 📋 Log List

A list of log cards sorted newest-first. Each card is two rows:

### Header row

| Element | Description |
|---|---|
| 🕒 Timestamp | HH:MM:SS.mmm in monospace |
| 🎚️ Level badge | Color-coded pill — debug=grey, info=blue, warn=amber, error=red |
| 📡 Method badge | GET=green, POST=blue, PUT=orange, DELETE=red (and others) |
| 🛣️ Path | Ellipsized |
| 📶 Status badge | 2xx=green, 4xx=amber, 5xx=red |
| ⏱️ Duration | Monospace; **orange** if > 1 s |

### Body row

- 🤖 Input model ID → ➡️ resolved output model (green)
- 🔌 Provider name
- 🟣 Alias group chip (when an alias was used; accent tint)
- ❌ Error text (red, when present)
- 💾 Cache hit rate chip (when payload capture is on and cache info is available)

Card background tints by severity:

- 🔴 Red — for errors
- 🟡 Amber — for 4xx responses
- 🟢 Accent (default) — for normal entries

## 🔎 Controls

### 🟢 Live Indicator

Animated pulsing dot in the app bar showing the stream state:

| State | Color | Meaning |
|---|---|---|
| 🟢 **Live** | Green | Streaming |
| 🟡 **Paused** | Grey | Stream paused (you tapped pause) |
| 🔴 **Offline** | Red | Disconnected / retrying |

### ⏬ Auto-Scroll Toggle

The auto-scroll button in the app bar:

- ⏬ **Auto-scroll on** (default) — the list follows the newest entry; tapping enters manual scroll mode
- ⏸ **Auto-scroll off** — list freezes where you are; new entries appear at the top but the viewport doesn't move

A new-entries banner appears at the bottom when auto-scroll is off but new entries have arrived. Tap it to jump to the newest.

### 🧹 Clear Buffer

Trash-can icon. Removes every entry from the in-memory buffer and the visible list.

## 🔍 Filter Bar

A single text field at the top filters entries in real time. The match is **free-text across any of**:

| Field | Matched |
|---|---|
| Model name | ✅ |
| Resolved model name | ✅ |
| Path | ✅ |
| Provider name | ✅ |
| Provider ID | ✅ |
| Error message | ✅ |
| Alias group | ✅ |
| HTTP method | ✅ |
| Status code | ✅ |
| Message | ✅ |
| Log level | ✅ |

A **Clear** button appears when the filter has any text. Empty state messages adapt to the situation:

- ⚪ "Logs will appear here when requests are processed" (no entries at all)
- 🔍 "No entries match the current filters"

## 🔬 Inspector

Click any log row to open the Inspector. The Inspector is a full-screen page with an app bar + two tabs:

### 🪪 Meta panel (both tabs)

A card of selectable rows showing the request metadata:

- 📡 Method, 🛣️ Path, 📶 Status, 🤖 Model, 🎯 Resolved, 🔌 Provider, 🌐 Client IP, 🕒 Captured at

### Tab: Parsed

A toggle to switch between **Markdown rendering** and pretty-printed JSON, plus two cards:

| Card | Content |
|---|---|
| **Request (parsed)** | Content-type badge + parsed body |
| **Response (parsed)** | Content-type badge + parsed body |

Parsed sections include:

- **System** — text blocks (system prompt)
- **Messages** — role-styled message cards (🟣 purple=assistant, 🔵 blue=user, 🟢 teal=system) with content blocks
- **Tools** — expandable cards with name, description, and input schema JSON
- **JSON** — raw JSON rendered in monospace for unrecognized top-level fields

Content block types:

| Block | Visual |
|---|---|
| 🅰️ Text | Plain text |
| 🤔 Thinking | Collapsible section |
| 🛠️ Tool use | Amber background |
| 📦 Tool result | Green if success, red if error |
| 🖼️ Image | URL as selectable text |
| 📝 System reminder | Collapsible, tertiary color |

Below the bodies:

- 📊 **Usage line** — "N in · N out · N cached"
- ⚠️ **Incomplete-capture notice** — warning banner for truncated / incomplete captures

### Tab: Raw

Two raw cards:

| Card | Content |
|---|---|
| **Raw client request** | Content-type badge + truncated badge (amber) + copy button + pretty-printed or monospace body |
| **Raw downstream response** | Same layout |

A **Back to Logs** button returns to the list. If the entry has aged out of the capture buffer, the Inspector renders a 404 with **No captured payload — capture is disabled or entry aged out of cache** and a **Retry** button.

## 📐 Parsed-View Display Order

For every format TresorOne recognizes, the Parsed view **does not** mirror the raw JSON key order. The canonical sections are emitted in the order the model actually consumes the prompt:

| Format | Parsed Order |
|---|---|
| **Anthropic Messages** | `tools → system → messages` |
| **OpenAI Chat Completions** | `tools → system → messages` |
| **OpenAI Responses** | `tools → instructions → input[]` |
| **Gemini** | `systemInstruction → tools → contents` |

A small banner at the top of the Parsed view explains that the section order is the way the model consumes the prompt, not the order the raw JSON uses. Unrecognized top-level fields (`generationConfig`, `safetySettings`, `temperature`, etc.) still show up under the canonical sections as pretty-printed JSON.

## 📡 Stream Lifecycle

The stream is active while you're on the **Logs** tab. Switching to another dashboard tab pauses it; switching back resumes.

> **Note:** New entries can take a moment to appear on busy gateways.

## ⚙️ Payload Capture

Payload inspection is **opt-in**. To enable it:

1. ⚙️ Open **Settings → Payload Capture**
2. ✅ Toggle on — the gateway starts keeping the most recent request and response bodies in memory

The setting is saved on the gateway. With it off, the Inspector shows a "no captured payload" page for every entry; with it on, the most recent requests are inspectable.

:::info
Payload capture adds a small per-request memory cost and only stores the **original** request — before any plugin runs. This is intentional, so the inspector shows what clients actually sent, not the post-pipeline output.
:::
