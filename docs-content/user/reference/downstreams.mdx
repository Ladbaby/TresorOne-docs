# 🔌 Downstreams

A **downstream** is an LLM provider endpoint TresorOne calls on your behalf — OpenAI, Anthropic, Google Gemini, a self-hosted OpenAI-compatible gateway, etc. The Downstreams page is where you create, edit, and delete them.

## 📐 Responsive List Layout

The Downstreams screen picks one of two layouts based on the window width.

### 🖥️ Wide — Master / Detail

| Pane | Contents |
|---|---|
| **Left (master)** | Search field, scrollable list of providers, sticky "Add Provider" button at the bottom |
| **Right (detail)** | Selected provider's full detail (inline-editable) |

When nothing is selected the right pane shows an empty-state card prompting you to select a provider.

### 📱 Phone — List-Only

On a phone-sized window the master pane takes the full width; tapping a row opens the provider's detail on a new page. The visual contract is the same — same actions, just on a separate page.

## 🔘 Provider Row

Each row in the master list shows:

- 🟢 **The provider's logo** — fetched automatically
- 🏷️ **Provider name** (with overflow ellipsis on long names)
- ✅ **An ON/OFF pill** — green ON or grey OFF, indicating whether the provider is enabled

A search field at the top filters by name as you type; the empty state appears when no providers match.

## ✏️ Inline-Editable Detail Pane

The detail pane is **fully inline-editable** — every field saves as soon as you finish editing it. From top to bottom the pane shows:

### Header

- 📷 The provider's logo
- ✏️ An inline text field for the **name** — saves when you press Enter or move focus away
- 🗑️ Delete button — opens a confirmation dialog

### 🔌 API FORMATS

A wrap of toggle chips for the four supported formats:

- OpenAI — Chat Completions
- OpenAI Responses
- Anthropic — Messages
- Gemini — generateContent

Each chip has a vendor-logo avatar. Toggling a chip saves immediately.

> **Tip:** Multi-format downstreams let the gateway auto-translate between protocols without any explicit rule.

### 🔑 API KEY

A field with an eye icon. Tap the eye to reveal or hide the saved key. Typing a new value and pressing Enter saves the new key.

A **Fetch Models** button is hosted here too — see the Fetch Models dialog below.

### 🌐 API HOST

A field with a link icon, plus a copy-URL button next to it. The editor validates the URL scheme before saving.

### 🤖 MODELS

A header with the model count and a help icon, plus two action buttons:

- 🔎 **Fetch Models** — spinner while the dialog loads, then opens the Fetch Models window
- ➕ **Add Model** — reveals an inline input row with **Add** button

Beneath the actions, a responsive grid renders 1–4 columns depending on available width. Each model is a chip (icon + ID + remove button); swipe a chip to delete it.

## 📋 Downstream Form (3 Tabs)

The form opens when you create a new provider or edit an existing one. It has **three sections** with a Save/Cancel action row at the bottom.

### Tab: General

| Field | Required | Notes |
|---|---|---|
| 🏷️ Name | ✅ Yes | Min 2 characters. Display name. |
| 🌐 Base URL | ✅ Yes | Must be a valid URL. Help tooltip explains what goes here (e.g. `https://api.openai.com`). |
| 🔑 API Key | ◯ Optional | Obscured with visibility toggle. The existing key is hidden by the server. |

### Tab: Models

| Element | Description |
|---|---|
| `SectionHeader` | Title + optional subtitle |
| 🏷️ Model `Chip` Wrap | Each chip shows the model icon + model ID + × remove button |
| ➕ Add Model button | Reveals an inline text field + **Add** button |
| 🔎 Fetch Models button | Calls **Fetch Models** and merges the results into the grid |

### Tab: API

A header + the same wrap of toggle chips for the four API formats, with vendor logos. Toggling chips commits when the provider is saved, or updates the form when creating new.

### Action Row

- ↩️ **Cancel** — pops the form
- ✅ **Create / Save** — saves the provider

## 🔎 Fetch Models Dialog

The Fetch Models window opens from both the **detail pane** and the form's **Models** tab.

| Element | Description |
|---|---|
| 🏷️ Title | "Fetch Models from Provider" |
| 🟢 Status badge | "N added" with an animated counter |
| ❌ Close | × button (top-right) |
| 📜 List | Scrollable list of model rows (icon + model ID + add/added button) |
| ✅ Done button | Closes the dialog |

Each `+ Add` button adds just that one model. Models already on the provider show as **Added** so you don't accidentally add them twice.

After every CRUD operation that introduces new model IDs (alias create/update, downstream create/update), the app refreshes the icon index so newly-referenced models get their logos on the next render.

## 🖼️ Provider Logos

Provider logos are fetched automatically. A new provider row shows a generic icon until you fetch models, at which point the icons refresh and the row switches to a vendor logo if one is recognized.

## 🗑️ Deleting a Downstream

The delete button (top-right of the detail pane header) opens a confirmation dialog. On confirm, TresorOne sends the delete call and the gateway also removes:

- 💥 The provider from any rule that referenced it
- 💥 Any aliases that pointed at it

A snackbar confirms the deletion and the row disappears from the master list.
