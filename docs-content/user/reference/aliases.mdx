# 🏷️ Aliases

An **alias** maps a model name that your apps send (e.g. `gpt-4o`) to whatever provider + model you want behind it (e.g. Anthropic `claude-sonnet-5`). Aliases are grouped by **input model**, so a single group can map the same input to many outputs and you can hot-switch between them with one tap.

## 📐 Alias Group Layout

The Aliases page lets you drag any group's header to reorder. Each group is collapsible:

### Collapsed

Header card only, showing:

- 🟢 The provider's logo for the group
- 🏷️ **Group name** (the input model ID)
- 🟣 **Regex pill** — purple "regex" badge when the group is a regex match
- 🔢 **Option count**
- ⚙️ **Option** text button (opens the form to add a new option to this group)
- 🗑️ Delete button (removes the whole group)
- ☰ Drag handle

### Expanded

The header expands to reveal:

- 🟣 **Announced Names editor** (only when the group is a regex match)
- 📐 **Option grid** — cards wrap to 1–6 columns depending on screen width

## 🟣 Regex Aliases & Announced Names

When a group is a regex match, every incoming request whose model name matches the pattern is eligible for routing through this group. Adjacent to the header is the **Announced Names editor** — a way to publish multiple "names" for the model so clients can ask for any of them.

| Element | Description |
|---|---|
| Label | "Announced Names" with a tooltip explaining how regex matching works |
| 🏷️ Existing names | Pills; × on each removes it |
| ➕ Add Name button | Reveals an inline text field + **Add** button + **Cancel** button |
| ⚠️ Validation | Error renders below the input row in red |

Updates save automatically, and if the call fails the change rolls back with a snackbar.

## 🧱 Option Cards

Each option card represents one provider + output-model pair for the input model.

### Active state

- 🟦 **Filled accent background** + accent border
- ⭐ First row: the provider logo + output model ID (bold monospace)
- 🏷️ Second row: the provider's logo at 70% opacity + provider name

### Inactive state

- ⬜ Tinted surface + grey border
- Same row layout, but no accent fill

### Actions

- 👆 **Tap an inactive card** — activates the alias (deactivates its siblings in the same group)
- ❌ **Tap the × button** on the active card — deletes the alias (opens a confirmation dialog); if it was the only option in the group, a sibling is auto-promoted to active

> **Tip:** A group always has at most one active option. Promoting an option deactivates every other option in the same group so the next incoming request for that input model resolves to exactly one provider.

## 📋 Alias Form (3 Modes)

The Alias form opens in three ways:

### Mode A — New Group

- 🔤 Free text field for **Input Model ID** (the model name your apps send)
- 🏷️ **Provider dropdown**
- 📦 **Output Model multi-select grid** (or free-text fallback if the selected provider has no known models)

### Mode B — Edit Alias

- 🔒 **Input Model** is read-only with a lock icon + explanatory subtitle
- 🏷️ **Provider dropdown** (preselected to this alias's provider)
- 📦 **Output Model grid** (single-select — only this alias's output is highlighted)

### Mode C — Add to Existing Group

- 🔒 **Input Model** pre-filled and read-only
- 🏷️ **Provider dropdown**
- 📦 **Output Model grid** (multi-select — adds a new option to an existing group)

## 🎯 Output Model Field

The **Output Model** picker adapts to what the selected provider has:

### Provider has known models

Responsive card grid with tiles that wrap based on window width. Each tile shows:

- 🟢 Provider logo + model ID
- 🏷️ Provider name
- ✅ Checkbox indicator for selection state

### Provider has no known models (or none selected)

A free-text area where you type one model ID per line. Use this when the upstream didn't expose a model list or you want to plug in an ID that isn't in the catalog.

### Validation summary

Beneath the picker, a single helper line tells you the current state:

- ⚠️ Red — "Select one or more models above"
- ℹ️ Muted — "N selected: model-a, model-b, …"

## 🪄 Drag-and-Drop Reorder

Long-press + drag a group's header to reorder. The new ordering saves immediately and survives across app restarts.

> **Tip:** Reordering is by group, not by option within a group. To change which provider is "active" for a model, tap an inactive option card instead of dragging.

## 🖼️ Logos

Like the Downstreams page, alias cards show the provider's logo. New aliases default to a generic icon until you activate or render them at least once.

## ⚡ Hot-Switching Tips

- Switching the active option **takes effect immediately** — no restart, no client reload. The next incoming request for that input model resolves to the new provider.
- Multiple groups can match the same input model (e.g. an exact match `claude-opus-4-8` and a regex `claude-.*`). The gateway resolves in priority order — exact first, then regex.
- A group with no active option silently falls through to direct routing by the provider's known models, so you can leave groups in an "unwired" state without breaking traffic.

## 🗑️ Deletion Behavior

| Action | Result |
|---|---|
| Delete option | If it was the active option and the group has siblings, the next sibling auto-promotes to active. No traffic interruption. |
| Delete group | Removes every option for that input model. Future requests for the input model fall back to direct routing by the provider's known models. |
| Delete provider (from the Downstreams page) | The gateway also removes any alias that pointed at it. |
