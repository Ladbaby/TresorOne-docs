# 📏 Rules

A **rule** is an optional request-matching + transformation step. When traffic arrives, the gateway applies every rule whose matchers fit — rules never override the resolved provider; they only contribute to the **plugin pipeline** that runs before the request is forwarded.

## 📐 Rules List Layout

The Rules screen picks one of two layouts based on the window width.

### 🖥️ Wide — Data Table

A scrollable table with hover-highlighted rows:

| Column | Content |
|---|---|
| **Name** | Rule display name |
| **Path** | Pattern path (e.g. `*` for any path) |
| **Model** | Optional model filter |
| **Downstreams** | Comma-separated list of matched provider names |
| **Enabled** | Inline toggle + status dot |
| **Actions** | Edit + Delete buttons |

### 📱 Narrow — Card Stack

Each rule becomes a card with all fields laid out vertically and Edit/Delete buttons in the footer.

## 🔧 Available Plugins Reference

Below the rules table is a **read-only reference** section listing every plugin the gateway makes available:

| Column | Content |
|---|---|
| **ID** | Plugin identifier (used in pipelines) — e.g. `openai2anthropic`, `custom_header`, `fix_anthropic_images` |
| **Description** | One-line summary of what the plugin does |
| (icon) | A small extension icon on each card |

The catalog includes format converters for all supported API formats, header injectors, image-fixers, and other middleware. Tap any row to see its default options (rendered inline).

> **Tip:** See the dedicated [Plugins](plugins) page for a quick-reference landing that surfaces common plugin IDs without forcing you to open the Rules form first.

## 📋 Rule Form

The form scrolls vertically and is divided into five sections:

### 🪪 Basic Configuration

| Field | Required | Notes |
|---|---|---|
| 🏷️ **Name** | ✅ Yes | Display name for the rule |
| 🛣️ **Pattern Path** | ✅ Yes | URL pattern (default `*`); supports `*` glob semantics. Help tooltip shows examples. |
| 🤖 **Pattern Model** | ◯ Optional | Optional model filter — leave empty to match any model |

### 🎯 Match Format

A header + multi-select chips for the four input request formats (OpenAI / OpenAI Responses / Anthropic / Gemini) with vendor icons.

### 🔌 Match Downstream Format

Same chip pattern, but matching the **provider's** declared format instead of the request's. Useful for rules like "when forwarding to an Anthropic provider, always X".

### 🔗 Match Downstreams

A header + a chip-based multi-select for provider names. Multi-select; an empty selection means "any provider".

### ⚙️ Pipeline Configuration

A header + the **Pipeline editor**. This is where you chain **transformer plugins** that run in order before the request is forwarded.

#### Per-step UI

Each step card renders:

- 🔢 **Numbered circle badge** — the step's 1-based position
- 🛠️ **Plugin dropdown** — sourced from the gateway's plugin catalog
- ✏️ **Options form** — automatically generated from the plugin's options. For example, `custom_header` shows key/value pairs; `fix_anthropic_images` shows a single toggle.
- 🗑️ **Remove step button** — only present when the step is not the last one

Empty state:

> ⓘ **No pipeline steps configured**
> Add a step to transform or augment the request before it reaches the provider.

#### Add step

A **Add Step** button appends a new step card at the bottom of the list. New steps default to the first plugin in the catalog.

### Action Row

- ↩️ **Cancel** — pops the form
- ✅ **Create / Save** — saves the rule

## 🧪 Plugin Pipeline Semantics

- ➕ Rules **add** transformer steps to the implicit pipeline; they never override the resolved provider.
- 🔗 Multiple rules can match a single request; their pipelines are concatenated in priority order.
- 🎯 Priority: exact path+model > exact path > wildcard path (`*`).
- ↩️ Each transformer runs sequentially; failures bubble up and the request fails fast.

The exact plugin IDs and options are fetched live whenever the form opens, so newly installed plugins on the gateway side show up here without app updates.

## 🗑️ Deletion

The delete button on each row opens a confirmation dialog. Confirming removes the rule from the table; the gateway also strips the rule from any in-memory request-resolution state immediately.
